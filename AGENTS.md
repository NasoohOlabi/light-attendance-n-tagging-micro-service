Students receive only their own projected attendance, never notes or raw events. Role approval is server-owned; signup grants no application access. Database credentials and signing secrets stay in the Bun server and private local environment. Read `docs/architecture.md` before changing event semantics or retries.

## Validation and safety

- Run `bun run verify` before completing any repository change. For UI changes use `.agents/skills/verify-halaqa/SKILL.md` and the affected feature map. Run `bun run verify:release` before stable promotion/publication. Fix failed checks; document provider checks that cannot run locally.
- Append events only. Teacher transport permits GET and POST. Corrections reference existing event IDs. Projection uses database sequence order, never device clocks.
- Attendance choices and totals are Present, Absent and Excused. Project legacy early/late marks as Present while preserving original event payloads and exact retry identity.
- Parse external data with Zod. Use named payload variants and derive types from schemas. Single quotes, no semicolons; React functions and hooks; Tailwind for the teacher UI.
- Give distinct student/course values their own labelled table columns on desktop and labelled, vertically stacked fields on phones. Phone records and their controls must fit without horizontal scrolling, including grouped and searched attendance, roster, student portal and history. Keep primary actions visible; group secondary actions only when needed. Student selectors contain names only. In a selected course, show only that student's enrollment level; outside courses, show the current roster level. A blank course level stays blank, without a roster/other-course fallback.
- Course enrollment uses a searchable student list with membership switches and course levels. Keep course editing, membership and later grade entry on separate navigable screens. Course-context Add student reuses the normal form and creates the student/enrollment atomically; switching membership off preserves history and grades.
- Keep view filters in `src/queryState.ts`. Railway uses same-origin HttpOnly Better Auth sessions; server session checks establish identity; never put tokens or database URLs in query parameters, source, assets or logs. Only public Auth/API endpoints may be bundled.
- Use the shared Fuse.js matcher for free-text search. Keep choice filters and lookups of structured values such as dates, numbers and phone identifiers literal.
