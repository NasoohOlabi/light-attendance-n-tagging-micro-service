# Halaqa verification features

The public homepage, sign-in and notebook screens have no development-release banner. `e2e/home.spec.ts` checks its absence in English/Arabic across page transitions and mobile overflow.

Run the affected scenarios and the full UI suite as directed by the [verification skill](../SKILL.md). The synthetic same-origin fixtures exercise real browser controls and storage; they do not establish live Railway behavior.

`e2e/neon.spec.ts` covers sign-in, session restoration, account switching, failed and uncertain requests, retries, storage denial/corruption, competing tabs, malformed snapshots and reassignment. `e2e/roles.spec.ts` covers Student privacy and denial, Administrator approval, roster management, self-protection and reset validation. `tests/neon-api.test.ts` tests server authorization and projection; `tests/railway-integration.test.ts` exercises password reset against a disposable database. The historically named files exercise Railway-compatible same-origin boundaries.

`e2e/notebook.spec.ts` drives the sample notebook. `e2e/home.spec.ts`, `e2e/home-routing.spec.ts` and `e2e/wartaq.spec.ts` cover homepage, routing and design samples. `e2e/mobile.spec.ts` and the Arabic authentication case cover language, responsive controls and RTL. `e2e/pwa.spec.ts` covers public shell caching, private request bypass, install prompts, and the bilingual update notice and Refresh button. For an installed app, verify that a fresh link stays in the browser and the install strip stays hidden. An empty or failed lookup keeps the install controls available. Browser tests simulate install API responses on desktop and emulated phones. See [PWA behavior](../../../../docs/pwa.md) and [mobile audit](../../../../docs/mobile-and-languages.md).

The notebook opens on a dashboard. Verify the selected-date recording gaps, the six-session absence timeline and student contact/history navigation. On an Administrator dashboard, expand the theory and practical support lists, inspect missing evidence and open the selected course in Grades. Teacher dashboards omit course result readiness. Take attendance opens the alphabetized course roster; drafts survive search and filter changes. Add student opens the creation form for Administrators and sample users, without granting Teacher access. `e2e/dashboard.spec.ts` exercises these dashboard paths. Administrators open Settings explicitly. Course schedule details are placeholders; enrollment details are managed in Courses. Retain only synthetic screenshots and traces.

Table controls: Use the shared `TableToolbar` beside the title for each sortable list. `TableHeader` supplies the sortable columns on wide layouts and on the compact Courses table. Stacked records show their own labels and use the toolbar menus for every sort and filter field. `e2e/table-pages.spec.ts` verifies desktop column sorting, mobile menu coverage, 44px targets, number and date ordering, combined filters, and URL persistence. `e2e/table-controls.spec.ts` checks filtered bulk attendance and hidden drafts. Filter to a subset, mark its unmarked students present, and verify saved and drafted exceptions keep their values. Verify filters remain usable when no rows match.

At 320/390/430px in English and Arabic, verify roster, the attendance roster, summary, administrator register, course list, membership and grades, profile history, and student attendance history fit without horizontal table scrolling. Check labelled values and direct controls; retain desktop columns and confirm course levels and student privacy.

Courses uses inline action icons on wide lists and a three-dot menu on narrow lists. Grades and History & corrections use three-dot menus. Dashboard, Attendance, membership and form submissions keep their primary controls visible. Attendance rows show Add note next to the attendance control. On compact screens, tapping a name in Students opens Student information. The wide Students table has a dedicated Open student button, and the Administrator register has a direct Edit action. Account management keeps password reset beside its fields. Profile actions, overview filters, student portal refresh and public navigation use their existing controls.

Unsorted headings show Lucide chevrons on pointer hover or keyboard focus, with an 8px label gap and no size change on reveal. Active sort direction and priority remain visible; on devices without hover, all chevrons remain visible. `e2e/table-controls.spec.ts` checks idle/hover/focus, pointer cursor, ascending/descending/reset icons and spacing in English/Arabic; course geometry checks measure the label independently of its decorative icon.

Table configuration is closed by default behind small Sort and Filter icon buttons; Grades has Sort only. Header filter fields and active sort pills must not occupy the table's default layout. Open Sort to add, remove, change direction and drag column pills into priority order without duplicates. Exercise mouse/touch and keyboard reorder/drop/cancel, actual tied-row order, URL persistence and preview positioning under the production CSP. Open Filter on another table to select columns, combine text/choice conditions, edit/remove conditions and reset without losing hidden drafts. Verify popup close controls, Escape/outside dismissal and appropriate focus return. First Escape during keyboard drag cancels reordering; further Escape closes configuration. Switching languages must update screen-reader instructions. Check single-header/Shift-click shortcuts, reload, stale URL recovery and Grades' ignored stale filters. Verify English/Arabic desktop and 320/390px closed/open layouts, bounded popup scrolling and 44px targets. Configuration must not send writes.

Theme: `e2e/theme.spec.ts` checks device preference, explicit light/dark persistence, reset to device, and title-bar metadata that matches the page background. `e2e/pwa.spec.ts` checks the light startup fallback in the manifest. In an installed Windows browser window, verify that the native title bar matches the page after switching themes and reopening. In dark mode, check the charcoal navigation, attendance controls and follow-up card, muted blue primary action and soft-red absence dates in English and Arabic at phone and desktop widths. Inspect the public, sign-in, notebook, student and administrator surfaces, including status colors and table popups in both themes. The browser suite uses synthetic records.
