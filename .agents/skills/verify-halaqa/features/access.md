# Access and delivery

Sign in through the app or explore the sample. Run `e2e/neon.spec.ts` for synthetic same-origin Auth/API sign-in, session restoration, account changes, failed and uncertain requests, retry, unavailable or corrupt pending storage, competing tabs and malformed snapshots. Assert that failed storage or a held lock prevents unsafe additional writes and that retry retains event IDs. Run `e2e/roles.spec.ts` for approval, denied access, role isolation and Administrator password reset; confirm the acting Administrator cannot reset their own account.

Pending batches can contain private data. Web Locks and storage are required for safe live saves; reconcile uncertain batches before clearing storage. Synthetic tests do not prove live provider behavior.

Administrator entry and reload start on the dashboard with no account management. Open the profile avatar, then **Settings**; verify both `view=settings` and the older `view=administration` link. Accounts initially shows compact rows, with no visible role fields and no acting Administrator card. Focus an account summary and press Enter to open **Manage**, then verify role assignment and password mismatch validation. Switch between **Accounts** and **Students** and verify that only the selected section appears. A directory containing only the acting Administrator shows **No other accounts.** in English and Arabic.

Verify a single branded account header on notebook, Courses, Settings and Add student, plus the Student profile menu. An existing session photo renders as the avatar, with a fallback when unavailable. Open the profile menu by keyboard and pointer; check Escape restores trigger focus, outside clicks dismiss it, language switching preserves drafts/filters, and Sign out (Close session in samples) leaves the workspace. Settings remains Administrator-only. Check desktop and 320/390px English/Arabic layouts for touch targets, dropdown visibility and page overflow while keeping bottom page navigation usable.

Open **Profile settings** from the account menu for each authenticated role. Change the name and upload a synthetic PNG, JPEG or WebP image, save, reload and check the photo and name persist; remove the photo and save again. Check rejected oversized/invalid images and failed saves. Theme and language choices show their current selection with text and icons. `e2e/profile.spec.ts` uses synthetic sessions; `tests/profile.test.ts` covers the server validation boundary. Profile pictures are resized client-side before saving in the existing Auth user record. Live provider persistence remains a separate check.

Open **Add student** from the dashboard, save or cancel, and confirm Accounts/role controls are absent from the DOM. Verify the Settings directory and expanded editor at desktop/mobile widths, keyboard disclosure, Arabic RTL and no horizontal overflow. Teachers and Students cannot open Settings. Keep synthetic Settings overview/editor screenshots under ignored `.artifacts/verification/`.

Settings and Add student retain the notebook navigation. From Settings, open Dashboard, Attendance and Courses directly, then use browser Back to restore Settings. At 320px in English and Arabic, verify a single bounded navigation row with targets at least 44px wide and tall, and scroll the final Settings control above the fixed phone navigation. For app updates, run the real-worker case in `e2e/pwa.spec.ts`: replace the legacy cache-first worker, then change server HTML and use ordinary reloads to observe the new versions while another tab retains an unsaved note. Verify offline/stalled fallback, private request exclusions and preservation of unrelated scope caches. Update copy must ask users to save and refresh, without closing all windows.

During session and account restoration, verify the neutral workspace placeholder contains no sign-in, sample, sign-out or role controls. Hold the first notebook snapshot and confirm no zero counts or empty charts appear; check the selected query remains intact. Exercise session and account retry, including a late denial from an earlier timed-out account request, on desktop and mobile. Confirm Arabic RTL loading has no overflow. Refresh after loading must retain the visible snapshot.
