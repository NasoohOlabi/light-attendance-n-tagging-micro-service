# Courses and enrollment

Administrators open **Courses** to see every saved course, including courses with no students. The default is the list; **Create course** opens a separate page and returns to the list after saving. Create/edit a course, **Manage students**, and **Grades** are separate destinations with individual page headings and the notebook navigation retained. Course pages omit the generic notebook introduction and unrelated student count. The localized account role appears once in the header. Choose a course from its row rather than combining course/student selectors and scores in one form.

**Manage students** searches the existing roster by name. Each student has separate identity, current roster level, course level and enrollment columns. The switch enrolls or withdraws that student without deleting their enrollment, history or grades. A new enrollment starts with the roster level as an editable draft; an existing course level remains independent, including a deliberately blank level. Changing membership or level preserves both exam scores. Switching off blocks new attendance for that enrollment on the server.

**Add new student to this course** opens the normal student form with the course context and a course-level field. Saving creates the roster entry and active enrollment in one transaction, then returns to managing that course. Cancel returns without creating either. Stable IDs make a retry safe if a response is lost. The ordinary dashboard Add student flow remains separate from courses.

Enter practical (عملي) and theory (نظري) scores later on **Grades**, not during enrollment or student creation. Scores are optional numbers from 0 through 100, including zero. Saving grades changes only scores; it preserves membership and level. A student can belong to several courses with one stable enrollment per student/course pair.

Select a course in the notebook to mark its enrolled students and see that course's attendance, summary, dashboard and attendance history. The previous/no-course view shows historical unscoped records; enrolled students cannot receive new unscoped marks. Notebook note events remain student-scoped; performance notes on Grades belong to the enrollment. Existing attendance is not assigned to any course automatically. A student account receives only its own projected attendance with course names, never notes or raw events. Teachers see enrollments for their assigned active students, subject to their existing access and expiry restrictions.

**Summary** shows all recorded dates for the selected course and every student available in that course's authorized history, including inactive memberships. Course selection is its only filter; saved date ranges, student search, group and student filters from other pages do not narrow these totals. Student note counts cover all dates and remain student-scoped. **Previous / no course** summarizes unscoped attendance. Attendance, Notes and History retain their own controls.

The overview bars show Present, Absent and Excused as percentages of recorded student-sessions, rounded to one decimal place. Unmarked days are excluded; these are session shares rather than an average of individual student rates. With no recorded attendance, the overview shows an empty-state message. The student table retains exact counts.

The notebook **Students** list and both grouped/searched **Attendance** use the same course-level rule and keep student identity separate from the labelled Level column. With a course selected, Level shows only that student's level in that enrollment; a blank level displays an em dash. Attendance accordions group by this displayed level. Switching courses can show a different level for the same student. In **Previous / no course**, Level shows the existing roster level (the roster group value). Course levels never fall back to that roster value or to another enrollment. The existing Group filter still filters roster groups.

For Administrators, **Students** defaults to **All students**, showing the complete register, including inactive historical and unassigned students. Switching back from a course restores that full list and its count. Its separate **Courses** column lists every active enrollment's course name as a badge, including closed courses; withdrawn memberships are omitted and no enrollment displays localized None. The names stay separate from roster and enrollment levels. This read view leaves active status unchanged; inactive students remain ineligible for new attendance and notes, and current course/attendance/Grades views retain their existing scope. Teachers continue to see only their active assigned students. Other notebook tabs retain **Previous / no course** for historical unscoped attendance.

Inactive enrollments remain available for historical attendance, corrections and grades. Current attendance and current enrolled-roster/dashboard counts exclude them. Teacher assignment and Student privacy restrictions still apply.

Migration `neon/005-active-enrollments.sql` adds an active membership flag, defaulting existing enrollments to active, without deleting data. Backup versions 4 and later preserve that flag; versions 1–3 remain supported without silently hiding inactive memberships. Test against a disposable database first; synthetic tests do not verify the live provider.

Administrators can manually close and reopen a course from the course list. Closing does not depend on grades and preserves enrollments, grades and history. Closed courses remain in the management list but are omitted from notebook selectors; a previously saved course URL can still show history and corrections, while new attendance is rejected. Reopening permits attendance again. Notes remain student-scoped.

Apply `bun run db:migrate` through `neon/006-closed-courses.sql` before deployment. Existing and new courses default to open. Version 5 backups preserve course status; older backups restore courses as open and cannot compare successfully with closed courses. Test against a disposable database first.

Manage students records **Handbook received** independently for each existing enrollment. It defaults to false and survives withdrawal, re-enrollment, level and grade changes.

Course actions stay on one line. On phones, the five touch-sized icons sit directly beneath the separate course name and status cells; wider screens keep the three-column layout. Accessible names and tooltips identify each icon.

On Grades, each course has independent minimum attendance (default 70%), practical passing grade (default 80), and theory passing grade (default 80). Both saved scores must meet their own threshold and attendance must meet its threshold. Attendance is Present divided by Present + Absent + Excused; unmarked days are excluded, and no records yield an unavailable attendance and pending result. Corrections and legacy early/late marks follow the normal event projection. Save thresholds and each row separately. The Grades page enables Close course only after every active enrollment has both grades saved and all grade and threshold drafts are saved. Inactive memberships remain visible and do not prevent closure. Manual close/reopen on the course list remains independent of grading.

Migration `neon/008-course-grading.sql` adds the course thresholds. Version 7 backups preserve them; older backups restore defaults and comparison rejects non-default target thresholds.

Each Grades row saves through a disk icon with a localized **Save grades** accessible label and tooltip. Data tables use tighter body-cell padding and compact phone records; action and input touch targets retain their existing size.

Table headings provide quick single-column sorting. Hold Shift while clicking another heading to add a secondary sort. The compact sort strip shows each active column as a pill: use **Add column**, drag its grip to change priority, toggle its direction icon, or remove it with the close icon. Priority 1 is applied first; later pills break ties. Keyboard users can grab a grip with Space, reorder with arrow keys, drop with Space or cancel with Escape. **Reset sort** preserves filters; **Clear sort and filters** resets both. Help explains the shortcuts and combined column filters: text fields match contained text, and choice fields match the selected value exactly. No modifier key is needed to combine filters. Sort order and filters survive reload in the view URL.

Grades includes optional multiline enrollment notes, saved with each row. Notes belong to that student and course, survive membership and grade changes, and are visible only to authorized staff; student attendance responses exclude them. Migration 010 adds the field with an empty default. Version 9 backups preserve it; older backups cannot compare against nonempty enrollment notes.
