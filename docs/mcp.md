# Wartaq MCP

1. Add **Wartaq** as a remote **Streamable HTTP** server in your MCP client. Use `https://wartaqi.up.railway.app/mcp` and choose **OAuth**.
2. In the Wartaq browser window, choose the intended account or sign in with its verified phone number and password. For a new invitation, follow **Finish account setup in Wartaq**, choose your password privately, then return to the connection window.
3. Approve the requested scopes. Ask “Which Wartaq account am I using?” to check the connection with `get_account`. Students can then ask for their attendance. Staff can ask “Which courses can I open?”

The client lists tools for the current role and scopes. If a tool is missing, check the account, finish any pending invitation setup, and refresh the client’s tool list. Reconnect to grant a different set of scopes or use a different account.

## Permissions

| OAuth scope      | Access                                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| `mcp:read`       | View your account and the records and reports available to your role.                                 |
| `mcp:write`      | Make the changes available to your role. Admin mutations and offline conflict checks use both scopes. |
| `offline_access` | Refresh access while the originating Wartaq session remains valid.                                    |

Teachers can read and edit attendance, notebook notes and profile fields for active assigned students. Students see their own effective attendance and can manage their own profile. Administrators manage accounts, the full student register, courses, enrollment, scores, thresholds, handbook receipt and final grade decisions. Only grant write access to a client you trust. Use Wartaq's Accounts screen to generate a password reset message privately.

## Website workflows

| Website task                   | How to do it through MCP                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Profile and first sign-in      | Use `get_account`, `get_profile` and `update_profile` for access, display name and photo. Pending invitees use `complete_invitation_setup`. Invited users can open `open_invitation_profile` to edit personal contact details or change their password privately.                                                                                                                                                                                                                             |
| Student portal                 | `get_my_attendance` returns the signed-in student’s effective attendance and course names.                                                                                                                                                                                                                                                                                                                                                                                                    |
| Find a student or course       | Start with `list_courses` or `find_students`. Student search supports partial or misspelled names, Arabic variants, status, course, offset and limit. Use `get_student_details` for one profile, memberships, effective marks and tagged notes. `update_student` uses the previously read profile fields to detect concurrent edits.                                                                                                                                                          |
| Take attendance                | Call `get_course_attendance_view` with the course ID and date. Its session rows carry the student ID, enrollment ID and current event ID. For one student or a batch of selected students, send `sync_attendance` those IDs and expected versions. An unmarked row has a null event ID. Only active enrollments in an open course can receive new marks.                                                                                                                                      |
| Dashboard and summary          | Select `view: "overview"` on the attendance tool for that date’s recording gaps, follow-up across the last six recorded sessions, and all-date totals with ranked absence dates. Use `courseId: "none"` for previous unscoped attendance. `view: "chart"` returns numbered chart rows in English or Arabic. Open the returned Summary link for highlighting, named images, PNG, ZIP or device sharing.                                                                                        |
| Notes, history and corrections | `append_events` records attendance, tagged notes and reversals. A reversal names the original event ID and reason. Administrators can locate it with `get_notebook_history`, filtered by course, student, date or kind, newest first. Attendance is course-scoped and notebook notes follow the student. `get_notebook` returns the authorized raw history and `get_attendance_summary` returns the effective marks and notes.                                                                |
| Offline reconciliation         | `sync_attendance` and `sync_student` submit version-checked marks or phone edits and can retry stable note events. Reuse the original IDs, times and payloads on retry. Inspect conflicts before submitting a new change. The browser holds its own pending drafts and sync queue.                                                                                                                                                                                                            |
| Accounts and sign-in phones    | Administrators use `get_admin_board`, `grant_account`, `disable_account`, `invite_accounts` and `verify_account_phone`. Confirm phone ownership directly with the account holder. Changing a sign-in phone revokes that account’s sessions. Use `open_password_reset` with an optional account ID to generate and copy a replacement password privately in Accounts.                                                                                                                          |
| Register and course membership | `save_student` manages registration, assignments and active status. `save_course` creates or renames a course. `get_course_workflow` with `view: "membership"` searches the complete register, including withdrawn or never-enrolled students. Use `save_enrollment` for membership, course level or teacher, and `set_handbook_received` for the handbook. `create_student_in_course` creates the student and enrollment together.                                                           |
| Grades, readiness and closure  | Use `get_course_workflow` with `view: "readiness"` for missing evidence and below-threshold scores. The `grades` view includes attendance, scores, calculated and effective results, decision history and closure eligibility from saved grades. `missingScores: true` selects outstanding active enrollments. Use `save_grades`, `set_course_thresholds`, `save_grade_decision` and `set_course_status` for the corresponding changes. Manual closure can advance eligible students’ levels. |
| Excel and row exports          | `export_course_report` supports full, grades, students, attendance and exam-participant reports. Rows and XLSX use the same default columns as the website. Pass `columns` to choose fields and their order, including optional contact fields on student and full reports. Filters cover enrollment, student, course level, score coverage and result. The attendance report also accepts dates and a mark.                                                                                  |

For example, ask “Who still needs attendance for this course on November 21?” to read a session, or “Show me students missing a practical score and their enrollment IDs” to start from readiness. The attendance date uses `YYYY-MM-DD`. Grade scores of zero count as saved.

Use the browser for device account switching, password entry, appearance, installation, sharing and unsent offline drafts. The original direct-client tools `update_invitation_profile` and `reset_account_password` still accept explicitly supplied credentials for trusted programmatic clients. Use the private browser links for interactive password changes.

## Private invitation messages

Create an invitation with `invite_accounts` after the administrator confirms each phone number directly with its recipient. Each person in the request needs a `phone` and `phoneConfirmed: true`. Select **Open private invitation** in the MCP app card, or open the Wartaq link returned by the tool. On your phone or desktop browser, sign in as the same Wartaq administrator who created it, then choose **Reveal invitation** and copy each recipient's message. MCP returns only a link and its reference. Wartaq delivers the message directly to your signed-in browser.

The link can reveal the message once within 15 minutes. Copy it before leaving the page. If the link is unavailable or the account was created before this feature, use **Settings → Accounts → Manage → Reset password** for the existing account to generate a fresh copyable message. This replaces the old password and revokes the recipient's sessions.

## Protocol and local verification

The server supports OAuth authorization-code flow with S256 PKCE, HTTPS client ID metadata documents and dynamic client registration. It advertises the issuer through protected-resource metadata, binds access tokens to `/mcp`, supports DPoP and rotating refresh tokens, and accepts token revocation. Signing out of the originating Wartaq session ends the connection. Role and roster changes apply on the next call.

For a local client, use the configured Bun origin followed by `/mcp`. Apply the Railway Auth and application migrations to a disposable database, set `TEST_RAILWAY_DATABASE_URL`, and run `bun test tests/mcp-integration.test.ts`. This exercises OAuth, the tools exposed to each role, pending setup, phone replacement, reports and private invitation redemption. The focused `tests/mcp-*.test.ts` suites also exercise the SDK with synthetic notebook records. `e2e/mcp-consent.spec.ts` checks the setup handoff and `e2e/invitations.spec.ts` checks the private viewer and clipboard in English and Arabic. Use synthetic accounts and keep traces off for live authentication.
