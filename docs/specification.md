# Notebook specification

The application supports a public course homepage, an isolated sample notebook and authenticated attendance and tagged notes in English and Arabic. Signup creates an identity but an Administrator must approve an application role. The [role matrix](roles.md) defines access and [assigned roster](assigned-roster.md) defines assignment.

Teachers select a date and mark students individually or mark only the visible unmarked students present; unmarked students are not implicitly absent. **Add note** on an attendance row opens a dialog for that student and session date. The dialog shows saved notes for that day and saves new notes independently of attendance. Teachers can leave tags blank to use the default attendance tag. History retains originals and supports append-only corrections with reasons. Administrators manage accounts and assignments; Students see only their own effective attendance. The notebook starts on a dashboard with effective attendance counts for the selected date, including unmarked students, and a recent chart of marked students for up to five recorded dates through that date. Continue attendance opens a partly marked session for the same course and date. Attendance table filters keep unsaved marks for hidden students. The pending save stays within reach on phones. Staff can open student information from a name and return to the attendance list. Administrators and sample users can open a student creation form; Teacher permissions are unchanged. Administrators open Settings explicitly.

Events are ordered by database sequence and retries retain event IDs. Pending batches survive uncertain delivery and must be reconciled before new writes; see [architecture](architecture.md). Browser samples and synthetic verification do not prove live provider behavior.
