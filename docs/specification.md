# Notebook specification

The application supports a public course homepage, an isolated sample notebook and authenticated attendance and tagged notes in English and Arabic. Signup creates an identity but an Administrator must approve an application role. The [role matrix](roles.md) defines access and [assigned roster](assigned-roster.md) defines assignment.

Teachers select a date and mark individual or displayed students; unmarked students are not implicitly absent. Notes have dates, tags and a student. Filters and summaries reflect the selected roster and date bounds. History retains originals and supports append-only corrections with reasons. Administrators manage accounts and assignments; Students see only their own effective attendance. The notebook starts on a dashboard with effective attendance counts for the selected date, including unmarked students, and a recent chart of marked students for up to five recorded dates through that date. Taking attendance offers fuzzy student search or group accordions when the query is empty, retaining drafts across search and filter changes. Administrators and sample users can open a student creation form; Teacher permissions are unchanged. Administrators enter Administration explicitly.

Events are ordered by database sequence and retries retain event IDs. Pending batches survive uncertain delivery and must be reconciled before new writes; see [architecture](architecture.md). Browser samples and synthetic verification do not prove live provider behavior.
